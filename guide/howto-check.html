How to check a loop independently

Goal: trust a solution count without trusting the engine that produced it.

The example

qbf: a Shape 1 loop with a clause refinement, which every checker below understands. Open qbf

Three independent checks

  1. The reference variant. The blocking loop (template "Reference run") uses no refinement that could be wrong. Same count, both exhausted: the refinement removed no solution on this instance.
  2. Python clingo. python3 tools/cegarcheck.py examples/qbf.json --instance example --solutions all runs the loop with Python clingo and code that shares nothing with the page's Lua runtime (--mode block is the reference run). It covers one abstraction, one check and one link, and refuses, with a reason, any statement it does not model.
  3. Proof logs. Loop tab: Certificates and a recording with proof (tools/run.mjs --proof FILE). python3 tools/certcheck.py project.json log confirms the count from the log: every counterexample is an answer set, every refinement's certificate verifies, every solution has no counterexample, and nothing else is left.

These checks confirm one run. To check the strategy (the relevant set or the clause/3 rules) on many instances at once, use a space: node tools/audit.mjs qbf --space formulas --bound 6 runs the symbolic audit on every DNF with up to 6 terms over 6 + 6 variables, one bound after the other, and prints "sound up to k" or the smallest instance it breaks on (Audit, mode Space, on the page). --symbolic checks one instance the same way when it is too large for the audit.

Pitfalls

  • cegarcheck compares only solution counts of exhausted runs; candidate counts differ by design.
  • Loops it does not model (MARCO, IHS, OLL, Benders, chains, families) can be checked only by the reference variant and the audit today.
  • certcheck refuses proof logs of witness checks.
  • A space verdict is about the space up to its bound: it checks the strategy, not a run's count, and says nothing about larger instances.
