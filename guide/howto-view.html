How to write a domain view

Goal: see each step of a loop in the problem's own terms (a graph, a grid, a profile), not as lists of atoms.

The example

guide-03-hit-clique draws the graph, the deleted nodes and the surviving triangle. Open its view

Steps

  1. Start from a suggestion. Observatory, Domain view, Suggest a view writes a fragment view from the interface predicates and adds a views entry (New view starts from a commented skeleton instead). Edit this view opens its rules there, not in the Programs tab; the drawing follows as you type.
  2. The scene (#program scene.) draws what stays: nodes and edges, cells, items, from the instance and shared. It runs once.
  3. The frame (#program frame.) marks one step with the facts step/1, kind/1 (reject, solution, …), cand/1 (the candidate's interface atoms), cex/1 (the counterexample) and lit/2 (the refinement's literals): attr(E, fill, Class), emph(E), note("…").
  4. Check it against the trace. Move the cursor (arrow keys) and compare the drawing with the Output tab's trace of the same step.

Pitfalls

  • cand/1 holds only interface atoms that are not facts; draw what the instance fixes in the scene.
  • The view runs as plain clingo with the project's constants: a mistake shows as a clingo message, never as a crash.
  • Marks: node, edge, cell, item, rank, attr, emph, ghost, note, layout, pos; anything else is reported.
