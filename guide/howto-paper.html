How to turn a paper into a loop

Goal: you have an algorithm in pseudocode from a paper and want it as a CegarPlay loop, checked against the paper's numbers.

The example

Chapters 13–15 each end with a box that maps a paper's pseudocode onto a loop script; marco is the shortest complete case. Open marco

A checklist

  1. Find the solvers. Every SAT/ASP/MIP oracle in the pseudocode is a solver; name what each one guesses. The abstraction is the one whose formula grows.
  2. Find the interface. What does the check need to know about a candidate? Those atoms are glue/1.
  3. Find the refinement. "Add the clause …" is G.clause or G.core; "add φ[μ]" is a program part grounded per counterexample (A.expand); "block the seed and its supersets" is G.above.
  4. Find the outer control. "Repeat until unsatisfiable" is Shape 2; "for each model" is a search; "optimal" is A.solve(optimal); bounds are track.
  5. Write a blocking baseline first with the same solvers, and check that the paper's refinement gives the same answers (audit, reference variant).
  6. Compare with the paper's numbers on its examples: iterations are candidates, oracle calls are solver calls (Statistics tab).

When the paper uses something CegarPlay lacks

  • Interpolants or proofs: clingo produces none. Omission-based abstraction (queens-omission) is the nearest substitute.
  • A MIP solver for hitting sets: use an optimal ASP solver (A.solve(optimal)).
  • Incremental solving with assumptions: every solver keeps its state; assumptions are assume lists.
