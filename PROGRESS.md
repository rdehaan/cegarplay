## Improvements after the final review (2026-11-21)

- Bug: ACE editors built inside a hidden tab (fragments, loop, the Instructions'
  code examples) were cropped or empty until something resized them. `init.js`
  now resizes the editors of a tab when it is shown and after a project load.
- Ctrl+Enter / Cmd+Enter runs from anywhere (capture listener on `window`).
- Autosave: the project (with run history) is kept in `localStorage`
  (`cegarplay.project`) and restored at start-up unless `?file=` or `?fresh=1`.
  Loading an example or a file over an edited project asks first (`app.edited`).
- clingo messages: the runtime's logger rewrites `<block>:L:C` to
  `fragment:L:C` (line within the fragment) and adds `fragment/line/col` to the
  W event; the page marks these lines in the editors after the run (infos in
  blue do not set the red tab marker).
- Run-time errors: a hint sentence for common errors (`relevant/1 derived
  nothing`, glue derives nothing, no progress); the Lua traceback is collapsed.
- Trace panels: atoms flow inline, one line per predicate. When relevant/1
  derives nothing, the runtime first emits a trace step of kind `error` (even
  past the trace cap; the counterexample text only while tracing), and the
  trace view jumps to it.
- New project (Control tab): `Project.starterProject()`, four commented
  fragments that run as they are (downward-closed sets, n = 4 gives 4 solutions).
- The loop script is compiled 500 ms after each edit; errors are marked at once
  (`Editors.setMarks`).
- Run message under the run bar when a run ends in an error or does not
  start (visible from every tab, with a link to the Output tab).
- Output: "Download" next to Solutions saves all solutions (up to 200,000 kept),
  not only the 1,000 shown.
- Fixes after an independent review: two-line clingo locations mapped at both
  ends; a project opened with `?file=` (or a failed restore) does not overwrite
  the kept project until it is edited (`app.saveBlocked`); a stored project that
  fails to load falls back to the example; `Editors.build` clears marks; a run
  cancels the pending live check; trace groups by predicate regardless of sort.

## Known problems

- clasp's default enumeration (backtracking, `--enum-mode=bt`) does not keep
  refinement clauses added during `search` in force: later candidates may
  violate them (seen with `tutorial-weak-relevant` in Shape 1: unit clause
  `-pick(4)`, the next candidate has `pick(4)`). The result stays sound (every
  candidate is checked) but refinements prune less, and a too-weak relevant/1
  may lose no solutions in Shape 1. `options "--enum-mode=record"` on the
  abstraction solver keeps them (sum-free n=8: 77 instead of 107 candidates).
  cegar.py behaves the same (rows 1-3 equal its numbers), so the runtime is
  unchanged; the tutorial shows the weak-relevant loss with Shape 2.

## Sudoku examples (2026-11-22)

Two contrib examples (group `exists-forall`, not `fast`, `expected: null`: the runs stop at the
first puzzle, `solutions = 1`). Both are the 9 x 9 version of `fewest-clues` (same check: two
grids that agree with the clues; same clause refinement).
- `sudoku-unique`: k clues, unique solution. An instance may fix the solved grid with
  `solution/3` (`grid(s) :- not fixed.`, so the grounder makes the grid facts: each solve is
  much cheaper). Engine times (seed 0): free grid k = 26 0.4 s, 25 2.3 s, 24 14.5 s, 28 56 s
  (search luck, not monotone); k <= 21 does not finish in 4 min, also with a fixed grid at
  k <= 19, so **17 is out of reach** of this loop. (An instance that printed 14 clues of a known
  17-clue puzzle, k = 3, was dropped on request.)
  Uniqueness lemmas in A (deadly rectangles, two clueless rows in a band, two unshown values)
  did not help reliably; not used.
- `sudoku-hard`: also not solvable by naked/hidden singles, naked/hidden pairs and locked
  candidates (fragment `beginner`). A *guesses* the pencil marks (out/known) and requires them
  to be closed under the techniques with a cell left empty: such a set exists iff the least
  fixpoint is incomplete. (A positive least-fixpoint encoding was ~10x slower: unfounded-set
  checks.) Deductions are sound, so rules only derive the values of the grid s: small grounding
  (83k rules on a fixed grid). The free witness gives many models per puzzle, so A has
  `options "--project"`; `tools/cegarcheck.py` now blocks accepted candidates on the interface
  atoms when A has `--project`. Example: fixed grid, k = 26, 7 s; free grid k = 32 34 s.
- Checks: the beginner fragment agrees with a Python reference solver on 312 puzzles (incl.
  ones that need only pairs, only locked candidates, both). Small instances: engine = Python
  clingo (clause and block modes) = brute force (one-clue-missing: 7 unique / 3 also hard;
  rectangle-one: 8 / 0). `tools/audit.mjs` runs out of memory on these (9 x 9).
- `sudoku-symmetry` (requested: symmetry breaking): fragment `symmetry` in A, on only without
  printed clues or a fixed grid (`free`): first row of s = 1..9, rows 2-3 / 4-6 / 7-9 ordered by
  column 1, bands 2-3 by their first cell (all compatible: the row moves never touch row 1). Does
  **not** help: single runs (seed 0) at k = 24: plain 19 s, full symmetry > 120 s, relabelling only
  9 s, row order only 17 s; k = 25: 47 s full vs 2.3 s plain. The hard part is choosing clue cells.
- `sudoku-unavoidable` (requested: smarter loop): interface = grid cells + clue cells; C finds a grid
  b equal to s on the clue cells, `moved` = the unavoidable set D; clause "s changes on D or a
  cell of D is a clue" holds for every grid with s's values on D (sound: in each unit s and b hold
  the same values on D). Loop: up to 3 disjoint sets per candidate (`fix/2` assumptions built with
  `C.atom("fix", ...)` into a list; loop constants are not allowed outside family ranges, so the 3
  is literal). k = 22 free grid 13 s (plain: k = 23 > 120 s), k = 21 fixed grid 9 s; k = 20 > 5 min
  in every variant tried. Tried and dropped: `#minimize` + `optimal` (smallest set; 5-10x slower),
  a `#heuristic` preferring b = s, 1 vs 3 vs 6 sets (1 and 3 similar), adding symmetry breaking or
  deadly-rectangle lemmas (no consistent gain; one lucky k = 21 in 14 s with symmetry).
  Small instances: engine = cegarcheck (auto and block) = brute force (7, 0, 8).

## Puzzle generators (2026-11-23)

Three more contrib examples in the `sudoku-unique` pattern (guess a solution and the clues; C

`expected: null` (runs stop at the first puzzle). Generator source kept out of the repo; the

  0.8 s; 6 x 6 k = 5 21 s; 8 x 8 k = 12 9 s; 10 x 10 k = 24 6 s (k = 20 > 60 s).

  > 120 s); 6 x 6 12 signs 13 s; 7 x 7 18 signs > 120 s.
- `akari` (Light Up): A also designs the black cells (half-turn symmetric, `blacks` of them, or
  `layout/2` from the instance) and chooses `k` numbered ones; the lighting stays private.

  fail for a or b. 7 x 7 12 blacks k = 4 0.4 s; 10 x 10 20 blacks k = 8 1.6 s.

- `slitherlink`: one loop along grid edges; numbers 0..3 on cells. Rules (both solvers): degree

  tiny loops that a few zeros pin down). **Bug found on the way:** with the interface at 0..3 but

  Timings: 7 x 7 k = 12 len = 28 5.6 s; k = 10 len = 28 > 120 s; k = 10 len = 0 1.7 s;

  516; 4 x 4: 9,349 loops, 128 / 0 / printed 8 / len 12 2,104) = cegarcheck (auto, block).

## Voting group: Theta-2-complete winners (2026-11-25, on request)

A new library category **Voting** (`voting` in `tools/library.mjs` GROUPS and
`tools/make-examples.mjs` CATEGORIES); the old "Games and social choice" is now "Games and other
social choice". `kemeny-control` and `voting-justification` moved to Voting. Four new contrib
examples, one per Theta-2-complete rule, each with a different loop as its default:

- `kemeny-winners`: implicit hitting sets; majority cycles are the minimal unsat cores (MUSes) of a
  ranking check; the winners come from bounds (the first ranking found has the best score; a winner
  whose lower bound exceeds it is ruled out). Variants `plain-cores`, `disjoint-cores`,
  `lazy-transitivity` (Conitzer, Davenport and Kalagnanam: 3-cycles as clauses from relevant/1),
  `reference`.
- `slater-winners`: OLL (core-guided, totalisers by `C.expand(relax, core = K)`), then one query per
  candidate under the final assumptions, whose models are exactly the Slater rankings. Variants
  `plain-cores`, `ihs`, `lazy-transitivity`, `reference`. Same fragments as kemeny-winners; only
  `w/3` in `shared` differs.
- `dodgson-winners`: Theta-2 as P^NP[log]: binary search over the score, one NP query per step
  (`C.ground(bound, k)` grounds each bound), then one query per candidate. Variants `linear-up`,
  `linear-down`, `exists-forall` (the Sigma-2 template with one-literal clauses `atmost(S)`). No
  blocking variant: its last unsatisfiable call blows up even on 5 candidates.
- `young-winners`: row generation: each opponent that still beats the winner grounds its majority
  constraint for every winner (`refine(k)`). Variants `cores` (cores that name the winner),
  `plain-cores`, `all-opponents` (no refinement), `exists-forall`.

Shared encoding: `ballot(V,(A,B,...))` of 3 to 12 candidates (the PrefLib importer's format) or
`rank(V,P,X)`, with optional `count(V,N)`; voters with the same ballot are interchangeable units
with symmetry breaking (Dodgson's `pass/3`, Young's `del/2`). Instances: four small ones (`example`
is one election of 8 voters on which the four rules pick four different winner sets), the F1
seasons 1956, 1964, 1970, 1978, 1991 and 1993 from PrefLib (dataset 00052, tagged `slow` and
`audit: false` from 9 drivers on; `f1-1991`, 31 drivers, has no expected count in kemeny-winners
and is tagged `open`: no Kemeny loop finishes it in two minutes, while Slater's OLL takes 1.7 s), a Latin-square election (`cyclic`, Dodgson score 17), and two
recipes of the new generators `election-mallows` and `election-latin`. Every expected count was
checked by brute force (small) or by independent clingo encodings with clingo's own optimisation
(F1; Slater 1991 and 1993 with `--opt-strategy=usc`). Each readme has a table measured with
`tools/bench.mjs` (suite `loops`). The Slater winner is Theta-2-complete by Lampis (STACS 2022), not
by Hudry's earlier paper. Audits: sound on every small instance for kemeny
(default, lazy-transitivity), slater (ihs, lazy-transitivity), young (default, cores; `--link G`,
since two links leave A); the exists-forall clauses are sound by the symbolic audit.

Loop language: `//` (integer division, Lua's floor division) so that a binary search can halve
an interval and name an atom with the result (`S.atom` needs a whole number). Manual (grammar,
expressions, the literature table, the library table), spec and a compiler test updated.

Deviation: the runtime cannot stop a single long clingo call at the time limit (`run.mjs` ends such
a run 2 s later with "did not stop at the time limit"); several variants hit this on the large F1
seasons, which is why those instances are tagged `slow`.


## Judgment aggregation group: six rules (2026-11-25, on request)

A new library category **Judgment aggregation** (`judgment` in `tools/library.mjs` GROUPS,
`tools/make-examples.mjs` CATEGORIES and `test/library.test.mjs`). Six contrib examples, one per
rule, each with a different loop as its default. They are written by `tools/make-ja.py` (one
source for the shared fragments, instances, generator, readmes); edit it, run it, then
`node tools/make-examples.mjs`. Counts come from `tools/ja-check.py` and are cached in the
contrib files (`--recount` recounts all).

| Example | Rule | Complexity | Default loop | Variants |
| --- | --- | --- | --- | --- |
| `ja-kemeny` | fewest disagreements with the judges | Theta-2-c | implicit hitting sets, MUSes of the majority judgment as minimal cores | plain-cores, disjoint-cores, lazy-constraints (Γ clause by clause from relevant/1), maxsat, reference |
| `ja-slater` | fewest majority judgments given up (= MCSA) | Theta-2-c | OLL, then models under the final assumptions | plain-cores, ihs, linear-down, maxsat, reference |
| `ja-leximax` | lexicographic by support | Delta-2-c | level by level: `#minimize` over the level assumed by `focus(R)`, optima kept as `atmost(R,G)` | linear-levels (SAT queries only), ihs (priorities), reference |
| `ja-msa` | agreement a maximal consistent subset of the majority | Sigma-2-c | MARCO: MSSes give the outcomes, MUSes listed `as mus` | cores, exists-forall (G.below), reference |
| `ja-young` | complete the majority of a largest subprofile with a consistent majority | Theta-2-c | row generation: conflicts learnt from minimal cores on `m2/2`; outcomes from a `--project` solver | plain-cores, direct, linear-up |
| `ja-dodgson` | fewest changed judgments (sets stay consistent) | Theta-2-c | doubling then binary search (P^NP[log]) | binary, linear-up, linear-down, direct |

Input (shared by the six, fragment `shared`): `issue/1`, the integrity constraint over the issues
in CNF as `cl/1`, `pos/2`, `neg/2` (the names of the `.jagg` importer), the profile as `voter/1`,
`yes/2`, optional `count/2`; `maj(X,S,M)` is the majority judgment. Outcomes are `in/1`. Young and
Dodgson read a constant `complete` (instances `*-complete`: the majority must also be complete).
Instances: JEHLS 2020 Example 2.1 (`example`), the doctrinal paradox, a consistent majority, a tie,
the Condorcet paradox and the Voting election `example` in the preference agenda (Kemeny/Slater
outcomes = the rankings of kemeny-rankings/slater-rankings: 2 and 4), two recipes of the new
generator `ja-random` (premises and conclusions, judges around a hidden truth), and tagged
`bench`: F1 1964 and 1970 in the preference agenda (Kemeny 26 and 3, Slater 30 and 3, as in the
ranking examples), `random-22a/b`, and `random-30/38/44` for Kemeny, Slater, Leximax and MSA only
(Young and Dodgson do not finish them in minutes with any loop or with clingo's optimisation).

Checked: every variant gives every expected count; audits sound on every small instance for the
loops that refine by clauses or cores (Kemeny default, plain-cores, disjoint-cores,
lazy-constraints; Slater ihs; Leximax ihs; MSA cores; Young default, plain-cores). Expected
counts: brute force (small) and independent clingo encodings (MSA: saturation) agree.

Deviations and findings:
- An `#external` atom is false unless assigned, so assuming it true is a contradiction; the
  query bounds (`within/1`, Leximax's `focus/1`) are choice rules, and the enumerations over them
  use `--project` (as do Young's and Dodgson's outcome solvers, whose models carry deletions or
  changes).
- `S.models()` on a solver with a `#minimize` enumerates only improving models (clingo's default
  opt-mode), so the enumerating solvers have none (Leximax's D next to C).
- `keep` and `count` are loop keywords and cannot be fragment names.
- Dodgson's binary search from a first model's changes (variant `binary`) starts far above small
  scores; the default searches by doubling first.
- Checked against the papers (PDFs from the user): Conati, Niskanen and Järvisalo JAIR 2024 and
  AAMAS 2023, de Haan KR 2018, Lang and Slavkovik ECAI 2014, de Haan and Slavkovik IJCAI 2019.
  Leximax is Delta-2-complete (JAIR 2024 Prop. 2.1, citing Endriss et al. 2020), not Theta-2 as
  first written; so the group spans Theta-2, Delta-2 and Sigma-2. MSA (their Condorcet rule) is
  Sigma-2 for the credulous question (LS14 prove the sceptical one Pi-2-c). Dodgson is MNAC of
  LS14 (Prop. 5, Theta-2-c) and Def. 11 of JAIR 2024; Young is Def. 10 of JAIR 2024 and HS19 (de
  Haan 2018's variant with a complete majority is `complete = 1`). The new instance `taxonomy`
  (HS19 Example 1 = LS14 Example 2) reproduces every outcome stated there. Leximax's default is
  JAIR 2024's Algorithm 5; Kemeny and Slater got a variant `maxsat` (their Algorithm 1); MSA's
  exists-forall clause is the candidate's, not the counterexample's of their Algorithm 3 (sound
  there only for a single query L).
- The `.jagg` importer reads its own `[variables]`/`[clauses]` sections, not jaggpy's real file
  format, and gives no profile; not changed.

## BSML: countermodels and natural deduction proofs (2026-11-27, on request)

Two new library examples (group `logic`), after rdehaan/bsml-sat and Aloni, Anttila and Yang,
*State-based modal logics for free choice* (2024). Both project files are written by
`python3 tools/make-bsml.py` (one source, so the shared fragments agree; `--check`);
`tools/bsml-check.py` checks them by brute force. Manual: *BSML examples*.

- **`bsml-entailment`** (Shape 2, 12 instances): a countermodel to premises |= conclusion is a
  model with at most n worlds (default 3) and a state s that supports the premises but not the
  conclusion. Formulas are terms (`bot ne neg and or gor dia box empty plus`); `plus(F)` is the
  enrichment [F]+, computed in ASP. Each formula becomes an evaluation tree with support and
  anti-support nodes; a modal node gets one child per world (the successor state that world
  needs), which replaces bsml-sat's choice of successor copies and needs no bound on copies.
  A guesses model, state and the substates for the premises; C looks for substates that support the
  conclusion; `relevant/1`: every in(W), rel(W,V) for V in a chosen successor substate of W (the
  whole row where all of R[W] is needed), val(W,P) where an atom is evaluated. A has a no-junk
  rule (unreachable worlds empty and last) and the fragment `smallest` (#minimize worlds, then
  arrows and true atoms): with `A.solve(optimal)` the first surviving candidate is a smallest
  countermodel and the loop stops. Such a run is not exhausted, so (as for maxsat-ihs) the
  instances with a countermodel carry `expected.optimum` (its cost: worlds, then arrows and true
  atoms) and the example is tagged `stops-at-optimum`; the instances without one end exhausted
  with 0 solutions. Variants: `reference` (blocking, n = 2: at n = 3 the blocking loop does not
  finish in 60 s; the smallest countermodels have at most 2 worlds, so the optima agree) and
  `lift` (clauses lifted from the ground programs: 2 candidates instead of 692 on
  dual-prohibition, so the hand-written relevant/1 is far from minimal there; 3.5 s instead of
  0.4 s on the example).
- **`bsml-proofs`** (8 instances): the countermodel loop first; if none, a proof search that
  grows by one line per round (`P.ground(line, t)`, external `goal(t)`, up to 10 lines), so the
  first proof is a shortest one. The system is Definition 4.1 (BSML with global disjunction,
  sound and complete). Lines are sequents (dep/2: the assumptions a line depends on; a rule
  discharges assumptions by formula), so there are no Fitch boxes and the side conditions are
  local. `box` is a connective with the extra rule `def_box` (box A <-> neg dia neg A, the paper's
  definition); □Mon only with one assumption plus `box_nec` (none). Formulas come from a finite
  universe (subformulas of premises, conclusion, `lemma/1`). Pruning that loses no proof:
  assumption lines first and sorted, every line used, no line that repeats an earlier formula
  with a superset of its assumptions (9 lines unsat: 5.5 s -> 2 s in Python clingo). The one
  solution is the answer: the countermodel (accepted as a solution) or the proof, whose cost
  is its number of lines (#minimize over the lines), checked as `expected.optimum`. The search
  stops growing when no derivation of t lines exists at all (with a small universe the program
  becomes unsatisfiable and clingo drops the external goal(t): P.atom would fail). Variants:
  `reference` (blocking countermodel loop, n = 2), `proof-first` (the proof search first: 5.7 s
  on wide-scope, which has no proof, against 0.03 s). `narrow-scope-enriched` (10 lines, about
  6 s) is tagged slow; the library instance is the 7-line proof of Section 1's
  dia((p & NE) or (q & NE)) |- dia p & dia q.
- **Verification.** `bsml-check.py models N` evaluates Definition 2.3 directly on every model:
  the counts with the same no-junk restriction equal the loop's countermodel counts without
  `stop` at n = 2 and n = 3 (wide-scope 28 and 26,248, global-disjunction 4 and 3,256, ...), and
  the 0/1 answers match on all 12 instances. `bsml-check.py rules` grounds the proof program
  without a goal and checks every line of random derivations ending in each of the 42 rules
  against all 2-world models: about 37,000 derivations, no unsound line after two fixes found
  this way: (1) ¬E's conclusion must be classical (beta ranges over ML), (2) `rule(i, a; b)` in a
  body is the pool `rule(i,a) ; rule(b)`, so the dependencies of ◇Mon/□Mon were lost (now
  `rule(i, a; i, b)`). The audit (`tools/audit.mjs bsml-entailment`, also on wide-scope,
  detachability, global-disjunction) reports sound.
- Not done: the BSML system of Section 4.3 (the ⊥NE-translation rules need substitution in
  ∨-distributive positions) and the rules for the emptiness operator (Definition 4.24); the proof
  search treats empty(F) as non-classical and has no rules for it. bsml-sat's symmetry breaking
  for directed graphs is not used (the no-junk rule and the minimisation suffice here).
  `tools/cegarcheck.py` refuses the default loops (they stop at the first accepted candidate).

## ASP(Q): quantified answer set programs (2026-11-27, on request)

Three new library examples (group `logic`, tag `aspq`), after Amendola, Ricca and Truszczyński,
*Beyond NP: Quantifying over answer sets* (TPLP 2019). All three project files are written by
`python3 tools/make-aspq.py` (one source; `--check`; `--qasp DIR` writes every instance as a qasp
file); `tools/aspq-check.py` checks them by brute force. Manual: *ASP(Q) examples*.

- **`aspq`** (two levels, any program, 9 instances): an instance is an ASP(Q) program as facts
  (`rule/2` with level 1, 2 or `c`, `head/2`, `choice/1`, `pos/2`, `neg/2`; its qasp text in the
  comment), parsed from the qasp format with clingo's AST. A meta-encoding (`meta`) gives the
  answer sets of level `level` with the outer atoms fixed (fix_P: an atom belongs to the first level
  that mentions it; a rule of a later level with an outer head only checks it). The check looks for
  an answer set of P2 that violates C. Default: a `relevant/1` written once for every program (a
  cone of influence from the violated constraint and the constraints of P2; when P2 has a cycle
  through negation, every atom of P2 keeps its value). Variants `lift` (no `relevant/1`) and
  `reference`. Measured: example 31 candidates (lift 31, reference 48); nine-links 34 in 0.04 s,
  lift 36 in 1.2 s, reference 384.
- **`aspq-deep`** (any depth, 6 instances): the families and `refute` of `qbf-deep` over the same
  meta-encoding, with `core.minimal` (20 candidates instead of 24 on the example, 10 instead of 16
  on no-repair, same time; variant `plain-cores`), plus `reference` and `search`. Example: build,
  cut, repair (∃∀∃, 14 solutions).
- **`aspq-minmax-clique`** (Minmax Clique, Ko and Lin; 5 instances): written level by level, ∀P1 ∃P2
  with empty C checked as the dual ∃P1 ∀P2 : ⊥, so a candidate survives only vacuously. Hand-written
  `relevant/1` (the blocks of the clique) and an optimal check for the clique over the fewest rows:
  three-per-block 38 candidates (first clique 67, lift 50 in 4.5 s, reference 729).
- **Found on the way** (all fixed before the commit): (1) the deep glue passed only atoms that a
  later level reads, so `accept M; S[1].add(G[1].block(M))` blocked other answer sets of P1 that
  differ only on unread atoms (undercounts on random programs; `search` was right): level 1 now
  passes all its atoms. (2) At an inner level the answer's atoms that later levels read must keep
  their values (the core of level i + 1 drops level i's atoms): `need/1` roots for them. Removing
  them was not caught with clasp's plain cores (they contained every assumption, which hid the
  gap); with `core.minimal` the instance `derived-read-later` catches it. (3) Supports of a true
  atom: keeping one is unsound on positive loops (`a :- b. b :- a. a :- o.`); all are kept.
  (4) `#show true(A) : ...` alone does not hide other atoms; `#show.` added.
- **Verification.** Brute force (`aspq-check.py`: no solver; the answer sets of a level are the
  least models of its reducts, guessed on the atoms that occur negatively or in a choice) agrees with
  every variant on every instance and on 360 random programs (depths 2 to 4, with negative cycles,
  inner rules with outer heads, atoms both chosen and defined). Mutations of the generic
  `relevant/1` (positive literals only; no fallback for negative cycles; no inner `need`) are each
  caught by an instance (`negative-literal`, `odd-loop`, `derived-read-later`) under five randomized
  seeds. Audits: `aspq` and `aspq-minmax-clique` sound on every instance (also the symbolic audit
  of `aspq`); `aspq-deep` cannot be audited (families, as `qbf-deep`).
- **pyqasp** (github.com/MazzottaG/pyqasp 0.0.1, `-s quabs -g gringo --no-wf --count-qans`;
  installed in a venv, the PyPI package `qasp` is an unrelated quantum library): agrees on every
  instance in its syntax (aspq, the Minmax Clique files in ASP-Core-2 syntax: 6, 0, 4, 4, 74) and
  on 280 random plain programs (240 with two levels, 40 with three). It differs on programs where an atom heads both a choice rule and
  a normal rule (`{a; b}. b :- a.`: 3 answer sets, pyqasp 2) and where an inner rule has an outer
  head (`a1 :- not a1.` in P2: pyqasp makes every candidate vacuous although a1 is a fact under
  fix_P1); clingo on P2 ∪ fix_P1(M1) agreed with the brute force there. It exits 20 without a count
  when P1 has no answer set (read as 0). pyqasp takes 0.2 to 4.5 s on the Minmax Clique instances,
  the loop 0.01 to 0.07 s.
- **Deviation**: the two-level default is the generic `relevant/1`, not `lift`, and `lift` is a
  variant. With `lift` as default the audit sweep (`test/audit.test.mjs`) reports `aspq` unsound:
  the audit checks a check's `relevant/1` atoms, not the clauses of a `lift` link (a pre-existing
  limitation, not changed; the generic `relevant/1` is also about as strong and 4 to 30 times
  faster).
- Tests: `cd test && CHROMIUM_PATH=/opt/pw-browsers/chromium npm test`: 1,511 tests, 1,412 pass, 0 fail,
  99 skipped (75 bench, 23 slow, 1 native clingo with Lua), 17 min. Every variant of the three examples
  gives every instance's count with `tools/run.mjs --instance all` (what `SLOW=1` coverage adds).
- Not done: disjunctive heads (the meta-encoding needs normal programs; saturation would be needed),
  bounds on choices and aggregates in the generic format, C with rules other than constraints,
  ASP(Q) with weak constraints (robust-facilities covers the outer case), and a domain view.
